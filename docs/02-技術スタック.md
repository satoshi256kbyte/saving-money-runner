# Saving Money Runner 技術スタック

本プロダクトが採用する技術ツール、フレームワーク、およびそれらの役割を記載。

## 本番環境（AWS）

### コンピューティング・イベント駆動

| サービス | 用途 | 理由 |
| --- | --- | --- |
| **Amazon API Gateway** | Webhook エンドポイント | GitHub からの安全なイベント受信、WAF 統合 |
| **AWS Lambda** | HMAC 署名検証、ランナー起動 | イベント駆動型での効率的な実行 |
| **Amazon EC2（Spot Instances）** | GitHub Actions ランナーの実行基盤 | 低コスト、自動スケーリング対応 |
| **Auto Scaling Group** | ランナー数の動的調整 | ジョブ負荷に応じた自動スケーリング |

### セキュリティ・管理

| サービス | 用途 | 理由 |
| --- | --- | --- |
| **AWS Secrets Manager** | シークレット管理 | 暗号化保存、監査ログ統合、ローテーション対応 |
| **AWS CloudTrail** | 全 AWS API 呼び出しの監査ログ | エンタープライズ監査要件への対応 |
| **VPC / Private Subnet** | ランナーのネットワーク隔離 | パブリック IP 廃止によるセキュリティ向上 |
| **AWS CloudWatch** | ランナー稼働状況のモニタリング | ログ集約、アラート設定 |

### インフラストラクチャ・イメージ管理

| サービス | 用途 | 理由 |
| --- | --- | --- |
| **Amazon EC2 Image Builder** | ランナー AMI のビルド・脆弱性スキャン | 定期的なパッチ適用と自動化された安全性検証 |
| **Amazon EC2** | ビルドサーバー、テスト環境 | AMI 構築の実行基盤 |

## インフラストラクチャ・コード（IaC）

### AWS CDK

本プロダクトのAWSインフラをAWS CDK v2のTypeScriptで管理する。

| 責務 | 詳細 |
| --- | --- |
| **AWS CDK** | API Gateway、Lambda、EC2、IAM、Secrets Manager等の構築 |
| **Construct** | セキュリティ境界と再利用可能なAWSリソース構成の定義 |
| **CloudFormation** | CDK synthで生成し、変更差分とデプロイ単位を検証 |
| **静的解析** | TypeScript、ESLint、CDK synthによる構成検証 |
| **ベストプラクティス** | Stack分割、Context lookup抑制、出力値の標準化 |

利点：

- AWSサービスの設定をTypeScriptの型検査で検証できる
- 顧客アカウント毎の再現可能なデプロイができる
- Constructとしてセキュリティ設定を再利用できる
- CloudFormationの差分とロールバックを利用できる

## ローカル開発・テスト環境

### Ministack

AWS リソース（API Gateway、Lambda）をローカル環境および CI で
エミュレーション。実AWSアカウントへのデプロイ前に以下のテストを実施可能。

| テスト種別 | 内容 |
| --- | --- |
| **結合テスト** | Webhook → Lambda → ランナー起動の一連フロー |
| **異常系テスト** | 無効な署名、権限不足などのエラーケース検証 |
| **権限バウンダリテスト** | IAM ポリシーによる最小権限の検証 |

利点：

- 開発サイクルの高速化（AWS リソース作成待ち不要）
- CI 上での完全な自動テスト実行
- 本番環境へのデプロイリスク低減

## パッケージ管理・デプロイツール

### PNPM

ユーザー環境へのデプロイを補助するスクリプトおよびローカル検証ツールを管理。

| 責務 | 詳細 |
| --- | --- |
| **依存関係管理** | Lockfile による完全な再現可能性 |
| **インストール高速化** | ディスク使用量効率化、重複排除 |
| **セキュリティ** | サプライチェーン攻撃リスク低減（Lockfile 検証） |
| **スクリプト提供** | デプロイ補助、設定検証、トラブルシューティング CLI |

## 開発・検証フロー

1. **ローカル開発** - Ministack でコンポーネント動作検証
2. **CI テスト** - GitHub Actions で Ministack ベースの結合・異常系テスト
3. **AWS CDK検査** - CDK synthとTypeScriptによる構成検証
4. **本番デプロイ** - CDK deployで AWS リソースとGitHub連携を一括構築

## セキュリティ考慮事項

| 要件 | 実装 |
| --- | --- |
| **IAM 最小権限** | Lambda、EC2 各リソースに独立した IAM Role を付与 |
| **通信の暗号化** | API Gateway(HTTPS)、VPC 内通信のデフォルト TLS |
| **シークレット管理** | Secrets Manager で GitHub App Token 等を暗号化・監査 |
| **ネットワーク隔離** | Private Subnet + Security Group による多層防御 |
| **イメージセキュリティ** | EC2 Image Builder による脆弱性スキャン、定期更新 |
| **監査証跡** | CloudTrail でユーザーの全操作を記録 |
