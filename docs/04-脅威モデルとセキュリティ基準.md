# 脅威モデルとセキュリティ基準

## 目的

Saving Money Runnerは、GitHubのイベントを顧客AWSアカウント内のLambda、Secrets Manager、
EC2ランナーへ渡す。外部入力、短命トークン、ジョブ実行環境、AMI、監査ログを保護し、
後続の実装Issueが同じ判断基準を使えるようにする。

本書はIssue #2の設計基準であり、具体的なAWSリソースやIAM Actionの実装は後続Issueで行う。

## 対象範囲

対象は、顧客Organizationに限定したGitHub App、Webhook受信、Lambdaによるイベント処理、
Secrets Manager、Private Subnetのエフェメラルランナー、AMIビルド、監査・監視である。
顧客ごとにAWSアカウントを分離し、共有コントロールプレーンはMVPの対象外とする。

## 保護対象資産

| 資産 | 例 | 主な脅威 |
| --- | --- | --- |
| GitHub認証情報 | App秘密鍵、Webhook Secret、短命登録トークン | 盗難、ログ漏えい、過剰権限 |
| Webhookイベント | raw body、署名、イベントID、リポジトリ情報 | なりすまし、改ざん、リプレイ、入力汚染 |
| AWSリソース | Lambda、Secrets Manager、EC2、IAM Role | 権限昇格、設定ミス、公開アクセス |
| ランナー環境 | AMI、ワークスペース、環境変数、生成物 | ジョブ間汚染、悪意あるWorkflow、データ持ち出し |
| 監査証跡 | CloudTrail、CloudWatch Logs、相関ID | 改ざん、欠落、Secret混入 |
| 顧客情報 | Organization、Repository、リージョン、リソース識別子 | 公開、越境参照、誤設定 |

## 信頼境界とデータフロー

```text
GitHub Organization
  └─ HTTPS Webhook（未検証の外部入力）
       ↓ SEC-001〜SEC-003
API Gateway / Webhook Lambda
  ├─ Secrets Manager（短命認証情報とSecret）
  ├─ GitHub API（最小権限・短命トークン）
  └─ EC2 / Auto Scaling（Private Subnetの一時ランナー）
       ↓ SEC-004〜SEC-007
ジョブ実行・破棄
  └─ CloudTrail / CloudWatch（マスキング済み監査証跡）
       ↓ SEC-008〜SEC-010
運用者・顧客管理者
```

GitHubと顧客AWSアカウントの間、WebhookとLambdaの間、Lambdaとランナーの間、
ランナーと監査基盤の間を信頼境界とする。境界を越える値は未検証または最小権限で扱う。

## 脅威と対策

| 脅威 | 対策 | 基準 |
| --- | --- | --- |
| Webhookなりすまし | raw bodyのHMAC検証、定数時間比較、Secretローテーション | SEC-001 |
| リプレイ・重複実行 | イベントID、受信時刻、冪等性キー、期限検査 | SEC-002 |
| 入力汚染・SSRF | イベント種別、Repository、ラベル、URLの許可リストと形式検証 | SEC-003 |
| GitHub権限の過剰付与 | Organization限定Private App、最小権限、短命トークン | SEC-004 |
| AWS権限昇格 | Lambda、ランナー、AMIビルド、運用者のRole分離 | SEC-005 |
| 外部からのランナー侵入 | Private Subnet、Public IPなし、Inbound拒否、TLS | SEC-006 |
| Secret漏えい | Secrets Manager、ログ・出力・Issueのマスキング | SEC-007 |
| ランナー汚染 | 1ジョブ1インスタンス、ジョブ後のワークスペース破棄 | SEC-008 |
| AMI改ざん・脆弱性 | Image Builder、スキャン、承認済み世代のみ配布 | SEC-009 |
| 監査不能・濫用 | CloudTrail、相関ID、レート制限、上限通知、異常検知 | SEC-010 |

## セキュリティ基準

基準の正本は`config/security-baseline.json`とする。本文は基準の意図と設計境界を説明し、
基準ID・検証方法・リリース阻止条件の整合性を自動テストで確認する。

| 基準ID | 基準 | リリース阻止 |
| --- | --- | --- |
| SEC-001 | Webhook raw bodyの署名を定数時間比較で検証する | する |
| SEC-002 | イベントのリプレイと重複処理を拒否または冪等に収束させる | する |
| SEC-003 | 外部入力を形式・サイズ・許可値で検証し、未検証値をAWS APIへ渡さない | する |
| SEC-004 | GitHub AppとトークンをOrganization・Repository・用途に必要な最小権限へ限定する | する |
| SEC-005 | Lambda、ランナー、AMIビルド、運用者のAWS権限を分離し、不要な権限を付与しない | する |
| SEC-006 | ランナーをPrivate Subnetへ配置し、Public IPと外部Inboundを許可しない | する |
| SEC-007 | Secret、トークン、顧客識別情報、未マスクARNをログ・出力・公開文書へ出さない | する |
| SEC-008 | ランナーを1ジョブで使い捨て、ジョブ後にワークスペースと一時認証情報を破棄する | する |
| SEC-009 | 検査・承認済みのAMI世代だけを配布し、失敗時は更新を停止する | する |
| SEC-010 | 監査証跡、相関ID、レート制限、同時実行上限、コスト異常検知を備える | する |

## リリース阻止条件

次のいずれかに該当する場合、実装が動作していてもリリースしない。

- 必須基準が未実装、検証不能、または自動検査が失敗している
- Webhook署名、リプレイ、入力検証、Secretマスキングを確認できない
- ランナーがPublic IPまたは外部Inboundを持つ
- ジョブ終了後にワークスペースまたは一時認証情報が残る
- 未承認AMI、脆弱性検査失敗のAMI、世代不明のAMIを配布する
- CloudTrailまたは必要なCloudWatchログが欠落する
- コスト上限、レート制限、同時実行上限がなく、濫用時に停止できない
- 検証ログ、Issue、公開文書にSecret、実アカウントID、未マスクARNが含まれる

検証不能は合格ではなく失敗として扱う。例外を許可する場合は、理由、期限、責任者、
代替対策を別途承認し、MVPの標準基準を変更しない。

## 残余リスクと後続Issue

| 残余リスク | 扱い |
| --- | --- |
| GitHub Workflow自体の悪意ある処理 | エフェメラル実行、Network制御、顧客のWorkflowレビューで軽減する |
| Workflowが取得する外部依存の脆弱性 | Lockfile、AMIスキャン、SCAを後続の品質ゲートで実施する |
| GitHub障害やSpot中断 | 再試行、上限、失敗通知をランナー実装で定義する |
| AWSサービスのリージョン障害 | MVPでは顧客指定リージョン単位の復旧手順を定める |
| 運用者アカウントの侵害 | 顧客のMFA、IAM管理、CloudTrail監査を前提とする |

## 検証方法

基準JSONの構造、基準IDの重複、必須カテゴリ、文書とのID整合性、公開識別情報の混入を
`security:check`で検査する。AWSリソースの実在性、IAM Actionの妥当性、Webhook実装、
ランナーのネットワーク分離は、それぞれ後続Issueの実装・結合・実AWS検証で確認する。
